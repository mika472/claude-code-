# お問い合わせフォーム 自動送信デモ（営業支援ツール）

企業のお問い合わせフォームへ、送信者プロフィールと営業メッセージを **自動で解析・入力・送信** する仕組みの実証デモです。
「AIで企業のお問い合わせフォームへの自動送信が実現可能か？」という問いに対する、**動く回答**です。

> 結論：**技術的に実現可能**です。本リポジトリで end-to-end の自動送信を実演し、その様子を録画（`demo.mp4`）しています。

---

## デモ動画

- `demo.mp4` … 構造の異なる2社のお問い合わせフォームへ、自動でフィールドを解析・入力し送信完了までを録画したもの（約28秒）。
- 緑の枠と吹き出しは「どの入力欄を何だと判定したか（解析結果）」を可視化したものです。

実演内容：
1. フォームの入力欄を自動検出（ラベル・placeholder・name属性を読み取り）
2. 各欄の意味を判定（会社名／氏名／メール／電話／件名／本文／同意チェック等）
3. 送信者プロフィールと営業文面を該当欄へ自動入力
4. 「ご用件」などの選択肢は意図に最も近い項目を自動選択
5. 個人情報同意にチェックし、送信 → 受付完了ページを確認

企業A（日本語ラベル・select・同意必須）と企業B（英語name属性・placeholder主体・姓/名の分割・メール確認用）という**作りの異なる2フォーム**で動くことで、汎用性を示しています。

---

## なぜ実現可能なのか（技術的な要点）

お問い合わせフォーム自動送信の核心は、**「企業ごとにバラバラなフォーム構造を読み解き、どの欄に何を入れるか判断する」**処理です。本デモでは次の構成で実現しています。

| 役割 | ファイル | 内容 |
|---|---|---|
| ブラウザ操作 | `src/auto-submit.js` | Playwright で実ブラウザを操作。フォーム検出→入力→送信 |
| フィールド判定（中核） | `src/field-mapper.js` | 各入力欄の意味を推定。**ここを LLM に差し替えると本番精度に** |
| 録画 | `src/recorder.js` | 操作画面を連番画像で収集し ffmpeg で mp4 化 |
| 疑似企業サイト | `src/server.js` | 検証用のローカルお問い合わせフォーム（2社分） |
| 送信内容 | `config/profile.json` | 送信者情報・営業文面・希望カテゴリ |

### フィールド判定について
本デモはキーワードスコアリング（照合元ごとの重み付け＋キーワードの具体性で判定）で実装しています。
入出力インターフェースはそのままに `classifyField()` を **Claude などの LLM 呼び出しに置き換える**ことで、
- 見たことのない言い回し・レイアウト
- 多段階フォーム、確認画面付きフォーム
- reCAPTCHA や画像認証を含むフォームの判別

への対応力を大きく高められます（ひな型を `field-mapper.js` 末尾に記載）。

## 実行方法

```bash
cd form-sales-demo
npm install
# ブラウザ取得（この環境では Chrome for Testing を .chrome/ に配置済み）
node run-demo.js
# → demo.mp4 が生成されます
```

> 注：通常は `npx playwright install chromium` でブラウザを取得します。本実行環境ではその配信経路が
> 制限されていたため、Chrome for Testing を直接取得し `executablePath` で指定しています。

## 運用上・法務上の注意（重要）

実在企業のフォームへ実際に送信する「フォーム営業」を行う場合は、以下を必ず順守してください。本デモはローカルの疑似サイトにのみ送信します。

- **送信先の利用規約・お問い合わせ目的の確認**：営業お断りの明記があるフォームへは送信しない。
- **特定電子メール法／個人情報保護法**：オプトアウト手段の明記、取得情報の適正管理。
- **送信頻度・量の抑制**：相手サーバへ負荷をかけない（レート制限・間隔調整）。
- **認証(CAPTCHA)の尊重**：ボット排除を意図した認証を回避する実装は行わない。
- **配信停止依頼への即応**：「今後の連絡不要」の意思表示には確実に従う。

打ち合わせ要約にあった「AIを前面に出さず、生産性向上・コスト削減のメリットで提案する」方針とも整合する、
**相手に配慮した運用**を前提とした設計にしています。

## KPI計測との接続（拡張余地）

打ち合わせで挙がった KPI（担当者接続率15%以上／アポイント率1%以上）に向け、本仕組みは
- 送信成否・受付完了の検知（本デモで実装済みの送信完了判定）
- 送信件数・到達件数・返信率のログ化
を組み込むことで、効果測定の起点として拡張できます。
